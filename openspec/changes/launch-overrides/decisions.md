# Decisions — launch-overrides

## D1 — Retire `state/profiles.json` in the seeding every command runs first

- status:   pending
- task:     0.6
- commit:   d183a72f
- trigger:  The only retirement path the application has, `retired_regions`, cleans AGENTS.md regions in a project's main working tree on a context reconciliation; nothing retires a file under `$UZE_HOME`.
- decided:  `UzeApplication::retire_records_of_earlier_releases` removes `UzeHome::retired_profiles_path` at the start of `ensure_default_plugins` (run ahead of every CLI command and by the workspace's startup worker) and of `setup_through`; a missing file is a no-op, so a settled machine pays one failed unlink.
- rejected: Hanging it on `retired_regions`: that runs per project and only on a reconciliation, so most machines would keep the file. A one-off marker recording that the retirement ran: one more record for a file that, once gone, nothing writes again.
- blast:    `setup.rs` (two call sites and the function), `UzeHome::retired_profiles_path`, two tests in `setup_tests.rs`.

## D2 — The CHANGELOG entry is written by hand under `[Unreleased]`

- status:   pending
- task:     0.8
- commit:

## D3 — Own the other ways a release resumes or relocates a conversation

- status:   pending
- task:     2.2, 2.3
- commit:   4fb4d844, ebdaf633
- trigger:  The design's owned list names session, resume, continue, fork, print and first-prompt flags; the snapshots show more flags that open a different conversation or start it elsewhere: Claude Code's `--from-pr` and `--teleport` resume one, and Codex's `-C`/`--cd` moves the working root away from the checkout whose rollouts the read-back matches by `cwd`.
- decided:  All three are `Uze`, refused with the continuity reason (`--cd` with "uze starts the agent in its own checkout"). Launch modes that take the session out of the pane (`--bg`, `--desktop`, `--cloud`, `--remote-control`, `--worktree`; Codex `--worktree`, `--remote`; OpenCode `--standalone`, `--server`; agy `--project`, `--new-project`, `--remote-control`) are left out of the catalogs, so they pass as unknown, as the spec says an uncatalogued flag does.
- rejected: Leaving `--from-pr`/`--teleport`/`--cd` out too: typed, they pass silently and the agent's continuity ends without a word. Owning the launch modes as well: each is a product decision (an operator may want `--remote-control`), not a collision with what UZE composes.
- blast:    Three entries across `claude/flags.rs` and `codex/flags.rs`; the left-out list is only module docs.
- amended:  by D25, D26 and D29. Launch modes are no longer left out: those that take the agent out of its pane, checkout or machine are `Uze`, remote control and agy's projects the operator's.

## D4 — Mark more flags than the design named as weakening or degrading

- status:   pending
- task:     2.2, 2.4, 2.5
- commit:   4fb4d844, 3d380070, b7278d79
- trigger:  The design names one `Weakens` (`--dangerously-skip-permissions`) and four Claude `Degrades`; each release has its own equivalents.
- decided:  `Weakens`: Claude `--allow-dangerously-skip-permissions`, Codex `--dangerously-bypass-approvals-and-sandbox` and `--dangerously-bypass-hook-trust`, OpenCode `--auto`, agy `--dangerously-skip-permissions`. `Degrades`: Claude `--safe-mode` and `--restricted`, which switch off the same deliveries `--bare` does. Value-level danger (`--permission-mode bypassPermissions`, `--sandbox danger-full-access`) stays `Operator` with the summary saying so, since the owner is per flag. agy's `--disable-slash-commands` is left out: it acts in print mode only, which is owned.

## D5 — A flag whose value is optional is offered as a switch and takes only an attached value

- status:   pending
- task:     2.2
- commit:   4fb4d844, d2a5e2a9
- trigger:  Claude Code's `-d, --debug [filter]` takes a value it may go without; catalogued as a switch, `-dmcp` was read as the cluster `-d -m -c` and refused for `-c`, while commander reads it as `--debug mcp`.
- decided:  `FlagValue::Optional(hint)`: only an attached value is the flag's (`--debug=mcp`, `-dmcp`, which takes the rest of its word as a value-taking short flag does), the word after it is never taken, and completion offers it as a switch whose summary names `--debug=<filter>`. Every flag a snapshot shows with a bracketed value is `Optional`, and `assert_catalog_in_help` fails otherwise: Claude Code's `--cloud`, `--debug`, `--from-pr`, `--prompt-suggestions`, `--remote-control`, `--resume`, `--teleport`, `--worktree`.
- rejected: `Free`, which would swallow the next entry as its value; a switch, which reads the filter's letters as short flags.
- blast:    One `FlagValue` variant, eight Claude Code entries, the help check, the reader's two value tests.

## D6 — A snapshot defines only the flags opening an option's own line

- status:   pending
- task:     2.6, 2.7
- commit:   8b4eb891, d1e96bc8
- trigger:  Reading every dash-led word in a `--help` let a flag mentioned in prose pass: Codex's top-level help says "use --last" in `resume`'s description, so a catalog listing `--last` passed the fresh-launch test.
- decided:  A flag is defined by a line indented at most six columns whose leading words are flags (`-c, --continue`, `--session, -s string`); wrapped descriptions sit deeper. The Rust helper (`flags_in_help`) and the Lab (`contract/flags.py::defined_flags`) read it the same way, so the Lab compares sets of flags, never wording. Snapshots were taken with `UZE_BYPASS=1`, `NO_COLOR=1`, `COLUMNS=100`, ANSI and trailing blanks stripped.
- rejected: A byte-for-byte diff in the Lab: help wraps with the terminal's width and vendors reword descriptions every release, so it would be red on noise.
- blast:    The helper in `shared/test_support.rs` and its Python twin; a vendor that indents options deeper than six columns needs the constant raised in both.

## D8 — The check takes the arguments UZE composed, not the plan

- status:   pending
- task:     3.2, 3.6
- commit:   d6370b54
- trigger:  The design gives `check` an `Option<&LaunchPlan>`, but `features.memories=false` is composed by the shim from `memory_off` after `plan_with` returns, so the plan alone cannot say whether that conditional key is set on this launch.
- decided:  `check(entries, catalog, managed, composed: Option<&[OsString]>)`, where `composed` is every argument UZE adds; `plan_with` passes the plan's `args` and `trailing`, and `LaunchOverrides::leave_out_composed(catalog, composed)` lets the shim drop, with a note, a flag that collides with what it adds afterwards (group 4 calls it with `memory_off`'s args).
- rejected: Moving the `memory_off` decision into `plan_with`: it is the shim's today and group 3 does not change the shim. Treating conditional keys as always owned at launch: it would refuse `-c notify=…` on every launch where the operator's own config already sets `notify`, which is exactly the case UZE leaves alone.
- blast:    The `check` signature and one method on `LaunchOverrides`; a plan-based signature is a wrapper over this one.

## D9 — Grammar details the design left open

- status:   pending
- task:     3.1, 3.2
- commit:   d6370b54
- trigger:  The design names the splitter's quoting and the verdicts, not the edge cases each meets.
- decided:  Double quotes take POSIX's escapes only (`\"`, `\\`, `` \` ``, `\$`), so a quoted `C:\dir` keeps its backslash; a backslash ending the line is itself. A catalogued flag that takes a value and has none, a `OneOf` value outside its set, and a keyed value with no `key=` are `Refused` with the reason (`takes a value: model`, `takes one of …`, `takes key=value`). Variable names are compared to the managed ones without case (`Path` is `PATH` on Windows). Keyed keys drop quotes and blanks around dots (`"hooks" . state` is `hooks.state`), and a key collides with an owned one when equal, its parent table, or inside it (`agents.max` under `agents`). A refusal note names a flag's spelling or a variable's name, never a value.
- rejected: Passing a value-less `--model` through for the harness to reject: the agent would start and die in its pane, where the popup could have said why.
- blast:    `overrides/line.rs` and `overrides/check.rs`, with their tests.

## D12 — A remembered set is its words, minus the secrets

- status:   pending
- task:     3.5

## D14 — The plan composes the launch; the shim prints one note

- status:   pending
- task:     4.1, 4.2
- commit:   e6f8bd12
- trigger:  4.1 asks the shim to splice overrides between the contribution's args and the first turn, and to apply memory-off's args after; the shim is a binary entry point no suite in `tests/` can call, so the order could only be proven by an acceptance test per harness.
- decided:  `LaunchPlan::compose(self, &mut contribution, memory_off, catalog) -> Option<String>` in `uze-workspace` folds the plan into the contribution in design decision 3's order, runs `leave_out_composed` with memory-off's args, and returns one note: the plan's own (which already holds what the plan left out, D13), then only what memory-off newly left out, then each `weakens` line. The shim calls it and prints the note once. A bypassed launch or a claim `owner_of` refuses says, through `continuity::overrides_left_behind`, how many overrides the agent has on that harness and why they were left out — a count, never a name, since the claimant need not be the operator; it is one `stat` when no record exists and never fails the launch.
- rejected: Keeping the splice inline in `src/shim.rs`: the order is a rule of the plan, and per-harness tests would have to go through a real binary for each harness.
- blast:    `LaunchPlan::compose` and `overrides_left_behind` in `continuity.rs`; the shim's block shrinks back if reverted.

## D15 — Launches that take overrides are `_with` siblings, and every placement answers what a bare launch needs

- status:   pending
- task:     4.3, 4.4
- commit:   0230beb5
- trigger:  `place_new_agent` has 69 callers and `resume_task` 8; the task asks for an overrides parameter. A harness started by its plain binary (no launcher, or no continuity) needs its overrides from the client, on every kind of launch, not only a new one.
- decided:  `place_new_agent_with(…, overrides: &[String])` and `resume_task_with(…, overrides: Option<&[String]>)` (`None` keeps what the agent had on that harness, `Some` replaces it), the plain names delegating with none. Every placement (new, resume, isolate, switch) ends in `launching_with`, which records the overrides under the agent's project for the harness its record now names, before the answer and so before the tab, and fills `AgentPlacement.bare_launch` from the record when `launcher` reports a gap — the same rule that names the launch. What a bare launch leaves out or weakens joins the placement's warnings. A record that cannot be written warns and launches without them.
- rejected: Changing the two signatures: 77 call sites for a parameter almost all pass empty. Letting the client compose bare launches from what it typed: a resume, an isolate and a switch carry recorded overrides the client never saw.
- blast:    `tasks/overrides.rs`, the `_with` methods, `BareLaunch` on `AgentPlacement`; group 5 calls the `_with` methods.
- amended:  after review. `resume_task_with` is gone: no product path resumes with other overrides, and a resume keeps the recorded ones through `resume_task`. `bare_launch` is filled whenever the agent has overrides on the harness, with what it leaves out on `BareLaunch.said` rather than the placement's warnings; whether the tab is handed them follows `AgentIdentity::through_launcher`, the command the client attached with, never a fresh look for the launcher.

## D19 — Overrides open on `ctrl+f` in the directory picker, for the operator to confirm

- status:   pending
- task:     5.1
- commit:   d61a75ea
- trigger:  The design leaves the new action's default chord to the operator; `ctrl+o` is the Global `SwitchMode`, `tab` the picker's `Expand`, `←→` the harness, and the picker takes typing, so a bare letter is text.
- decided:  `Action::OpenOverrides` ("open-overrides"), bound to `ctrl+f` in `Scope::RootPicker` only. A Ctrl letter is the one register every terminal delivers (`Tier::Universal`); `f` is not a control byte a terminal keeps (`ctrl+s`/`ctrl+q` flow control, `ctrl+i`/`ctrl+m`/`ctrl+h` are tab, enter, backspace), and no Global binding uses it, so it cannot collide while the picker is sealed. Mnemonic: flags. The operator should confirm or rebind it; the Keys screen already can.
- rejected: `alt+o`: `alt` is the extensions' family and host-conditional. `shift+tab`: reads as the reverse of completion. `f2`: no mnemonic, and function keys are the workspace's register for global doors.
- blast:    One binding in `load.rs` and the foot's hint text, which reads the keymap.
