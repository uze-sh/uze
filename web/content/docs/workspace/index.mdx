The workspace is the half of uze that runs your agents. Run `uze workspace`
and you get one terminal that holds all of them, each in a tab, on a
branch and, if you want, in a checkout of its own.

It runs the agents you already have, set up by `uze setup`. It does not need
any plugin: whatever [the package manager](/docs/plugins) delivered is there
in every agent it starts.

```bash
uze workspace
```

## What it does for an agent

- **A worktree of its own**, cut from your target branch, so agents never write
  over each other or over you. [Where an agent works](/docs/workspace/agents#where-an-agent-works)
- **A name** for its work, which becomes its branch. [Its work gets a name](/docs/workspace/agents#its-work-gets-a-name)
- **Delivery**: one click rebases it, runs your checks and merges it or pushes
  the branch. [Bringing the work home](/docs/workspace/agents#bringing-the-work-home)
- **Another harness**, mid-task: the same agent carries on in Codex, OpenCode or
  any other one set up here, briefed on what happened. [Continuing in another harness](/docs/workspace/agents#continuing-in-another-harness)
- **Nothing lost**: unfinished work is kept on a shelf, and **Recent** lists
  every agent no pane carries, across every project. [Work nobody finished](/docs/workspace/agents#work-nobody-finished)

## Spaces, tabs, panes

| | What it is |
| --- | --- |
| **Space** | A named group of agents, which can work in several projects. `Alt+S` adds one |
| **Tab** | A session inside it: an agent (`Alt+N`) or a shell (`Ctrl+T`) |
| **Pane** | The live terminal of the selected tab |

A new agent asks for the directory it works in, in a popup beside the space's
`new`, with its harness in a field that starts on the one you used last
(`←` `→` change it; `Tab` completes the directory). The directory starts on the project of the agent in front,
so another agent there is one `Enter` away. Rows mark the projects the space
already works in, with their branch, and the other Git repositories. A space can
hold agents of `front`, `back` and `landing` at once, and each agent's row
names its project.

A shell you open while an agent is selected belongs to that agent: it starts in
the agent's checkout and closes with it. A shell of the space belongs to no
project, wherever it goes.

`Alt+O` opens the [overview](/docs/workspace/space) of the agent in front: what
it was asked, the `agents.yaml` settings of the checkout it works in, and its
project's plugins, memory and worktrees.

The right end of the tab strip counts the selected checkout's changes
(`+12 -3`; click it to open [Code](/docs/workspace/code)). For an agent in your
own checkout it also shows what a pull would bring (`↓2`) and a push would send
(`↑1`). Click the pull count to fast-forward.

## Selecting text

The workspace owns the mouse, so it does the selecting your terminal would
otherwise do. Drag over text in a pane, a diff, a file, a spec or the agent
drawer, and releasing copies it to the clipboard. A drag past the edge scrolls
and keeps selecting, and a pane's selection reaches into its scrollback. The
copy travels as an OSC 52 escape, so your terminal has to allow it. In most
terminals, holding `Shift` while dragging skips uze and uses the terminal's
own selection instead.

## Nothing is lost when you close it

Your agents keep running when you quit the workspace, and are exactly where you
left them the next time you run `uze workspace`. After a reboot, uze starts
each agent again in the checkout it was working in, back in the conversation it
was having.

## When an agent finishes

An agent that finishes while you are looking elsewhere leaves a check on its
tab. To hear it too:

```bash
uze config notification on      # ring the terminal bell when an agent finishes
uze config notification silent  # never
```

## Extensions

An extension is something the workspace shows beside your agents. Three are
built in, and a plugin can bring more.

The built-in ones follow the order you read a change in: what it intends, how
the project is shaped, and what the code now is. Each opens where the
selected tab is and closes with the same key.

| | Key | Shows |
| --- | --- | --- |
| [Spec](/docs/workspace/spec) | `Alt+X` | The change the agent works from: proposal, design, tasks |
| [Architect](/docs/workspace/architect) | `Alt+A` | The project's diagrams |
| [Code](/docs/workspace/code) | `Alt+G` | What the agent changed, its files and a map of the checkout |

An extension a plugin brings stands in the bar under the agent area, in the
sidebar, in a drawer beside the agent or in a band over its pane. uze's own
marketplace has three, in the `workspace` plugin: **gsd**, **focus** and
**contributions**. [Official extensions](/docs/workspace/extensions) says
what each one shows and how to install them, and
[Extensions](/docs/plugins/creating#extensions) how to write your own.

### The Extensions screen

Under management (`Ctrl+O`), **Extensions** lists every extension on this
machine. The built-in ones wear **Bundled**, and those from uze's own
marketplace wear **Official**. Select one to open its drawer: the plugin it
comes from, whether it runs here, what it may reach, and its preferences,
which you set right there.

An extension a plugin brings runs nothing until you allow it. Press `Enter`
on it to enable it: a dialog names it and lists what it may reach, such as
reading the checkout, running `git` or typing into an agent, and **Allow and
enable** turns it on. Until then, where it would show, it says it needs
consent.

- Enabling one here turns it on in every project. One that reaches your
  agents is the exception: it is enabled one project at a time.
- An update that wants more than you allowed is **held** and runs nothing
  until you allow it again. One that wants the same or less is applied as it
  comes.
- A program an extension runs, such as `git`, is asked about on a step of its
  own, which says where it was found and whether it runs confined.
- Only you can allow one. An agent cannot answer for you from its pane.

When you open a project whose plugins bring an extension that is not enabled
there, the workspace offers it in one dialog, for that project or for every
project. Putting the dialog away answers nothing: it is offered again the
next time the project opens.

### Turning one off

The built-in ones are on until you say otherwise. Under management
(`Ctrl+O`), on **Extensions**, select one and press `Enter` to switch it off
or back on. The workspace follows at once: its button leaves the tab strip,
its keys go to the program in the pane, it leaves the action index (`F1`),
and its sidebar section is gone with it (the timeline for Code, the tasks for
Spec). `Enter` disables one a plugin brought in the same way.

The choice for a built-in one is kept in `~/.uze/config.toml`. From a
terminal, `uze config extension architect off` does the same, and
`uze config extension` lists them. You can also write it by hand:

```toml
[extensions]
architect = false
```

## Management

`Ctrl+O`, or the mark at the top right of the sidebar, opens management over
the workspace and closes it again: your plugins and marketplaces
(**Marketplace**), each agent's setup (**Integrations**), **Extensions**,
**Shortcuts**, and appearance and notifications (**Settings**), all with the
mouse.
