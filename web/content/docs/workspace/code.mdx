The files of the checkout the selected agent works in. What the agent changed
is read in the [Review](/docs/workspace/review), which opens a marked line here
with `o`.

| Key | Shows |
| --- | --- |
| `Alt+E` | The files. `p` switches a document between preview and source |
| `m` | A map of the checkout: where its code is, and what changes most |
| `Ctrl+F` | Search every file of the checkout |

The file you select stays selected when you switch between the files and the map.

## Editing

Click a line of a file to start typing there, or press `e`. `Ctrl+S` saves and
`Esc` stops typing. The line under the pointer and the line you type on are
highlighted.

A file counts as changed only while its text differs from the file on disk:
deleting a character and typing it back leaves nothing to save. You can move to
another file without saving. The changed file stays open, marked `unsaved` in
the tree, and comes back as you left it. Switching to another agent or tab keeps
it too: the surface comes back with its tabs and edits when you return. Closing
the surface with `Esc`, or its key again, asks once when something is unsaved.
Edits are kept in memory only. Quitting the workspace loses them, so save first.

## Tabs

Each file you open gets a tab over the content. A file you only pass over
takes the tab the previous one passed over had, so walking the tree leaves one
tab behind. Changing a file
keeps its tab. A tab with unsaved changes shows a dot where its close mark
would be.

| Key | Does |
| --- | --- |
| `Ctrl+PageDown` / `Ctrl+PageUp` | Next / previous tab |
| `Ctrl+W` | Close the tab. With unsaved changes it asks once, and closing again discards them |

## Search

Search has a tab of its own, beside the files and the map. Press `Ctrl+F` from
anywhere and type, or click the tab: on a search that already holds text, a
click lands on its results, and the field takes a click of its own. Results
update as you type: case is ignored,
and files Git ignores are skipped. Results are grouped by file, with a count for
each file. `↓` moves from the field to the results, `Enter` opens a result with
the caret on the match, and a click shows it while keeping the list in focus.
Matches are also highlighted in the open file.

Going to another tab keeps the search as it is, so you can check the tree and
come back to your results. `Esc` moves from the field to the results, then from
the results to the tree, opened down to the file you are on. The `×` at the end
of the field clears the search. Coming back to a search asks again, so it says
what the files hold now. A search stops at 2000 results.

Right-click a file or a directory, or press `Alt+.`, to copy its path (absolute
or relative), rename it, or delete it (`d`), asking first. There is no stage or
commit here: the checkout belongs to the agent working in it, and the agent
commits its own work.

The files hide what the project told its editor to hide: the `files.exclude`
patterns in `.vscode/settings.json`, read the way VS Code reads them.

## Timeline in the sidebar

While Code is on, a **timeline** section in the sidebar lists the recent
commits of the selected checkout, marking the ones not yet in the target.
Click one to read its whole message.
