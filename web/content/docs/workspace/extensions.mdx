Three tools are built into the workspace, in the order you read a change:
what it intends, how the project is shaped, and what the code now is. Each
opens where the selected tab is and closes with the same key.

## Spec

`Alt+R` opens the plans a spec-driven tool keeps in the checkout: each
change's proposal, design and tasks, and the specs that outlive them. uze
finds them on its own; there is nothing to declare.

| Subject | Lists |
| --- | --- |
| Changes | What is in flight, with how many of its tasks are done |
| Specs | The requirements that outlive the changes |
| Archive | Finished changes, newest first |

Changes are grouped by where they stand. **This checkout** is the change the
agent in the selected tab is working on, found from the files its branch
touched, and it opens first. **In progress** comes next, and **ready to
archive** holds changes whose tasks are all done but that were never
archived.

`p` switches a document between preview and source. `Enter` opens it in Code,
where you can edit it. `Tab` moves between the subjects.

Today it reads [OpenSpec](https://github.com/Fission-AI/OpenSpec) (an
`openspec/` directory at the root of the checkout).

## Code

/>

Everything about the checkout the selected agent works in.

| Key | Shows |
| --- | --- |
| `Alt+G` | What changed, with the diff |
| `Alt+E` | The files. `p` switches a document between preview and source |
| `m` | A map of the checkout: where its code is, and what changes most |

The file you select stays selected when you switch between them. In the files,
`e` edits a file and `Ctrl+S` saves.

Right-click a changed file, or press `.`, for what you can do with the change:
open the file, copy its path, or discard the change. Discarding asks once,
then puts the file back the way the last commit has it. There is no stage or
commit here: the checkout belongs to the agent working in it, and the agent
commits its own work.

## Architect

<Demo
  src="/uze-architect.gif"
  poster="/uze-architect-poster.png"
  alt="The architect surface: a C4 diagram drawn in the terminal, a box selected, then a level walked into."
  caption="Alt+A opens it; drag to move, click a box to see what it connects to."
/>

Your project's Mermaid diagrams, drawn right in the terminal. Click a box to
light up what it connects to; `Enter` goes inside it, `Backspace` comes back
out.

Tell uze where the diagrams live, in `agents.yaml`:

```yaml
artifacts:
  path: docs/architecture
```

### Ask an agent to draw them

You don't have to write Mermaid. Ask any agent, with the `uze:architect` skill:

```text
/uze:architect draw a C4 container diagram of this project
```

```text
/uze:architect add a sequence diagram of the login flow
```

The skill picks the right kind of diagram, writes it where the architect finds
it (setting up `artifacts:` if the project has none yet), and checks that it
draws. C4 views, sequence diagrams and flowcharts are supported.
