`Alt+N` starts an agent and asks which one. Each agent is a tab in the sidebar.

## Where an agent works

By default an agent works in your project, on your branch, like you would.

Or it gets **a worktree of its own**: a separate checkout of the repository
under `.worktrees/`, on a branch of its own. Two agents can then never touch
each other's files, or yours.

- **One agent:** right-click it → **To worktree**. It moves to its own worktree
  and takes your uncommitted changes with it, as a copy. When the tree holds
  uncommitted work, **To worktree, no changes** cuts the worktree from the last
  commit instead and leaves the changes where they are.
- **Every agent in a project:** declare it once in `agents.yaml`:

  ```yaml
  workspace:
    worktree: always   # manual (default) | always
  ```

Checkouts are reused, so a second agent does not pay for a fresh
`node_modules/` or a cold build. Two free checkouts stay warm for the
next agents and gives the disk of any other one back, and a free checkout
unused for three days goes too. Both numbers are yours to change:

```yaml
workspace:
  spare: 2       # free checkouts kept warm
  idle_days: 3   # after this long unused, even a spare goes
```

A checkout is only ever reused or removed when uze made it, and never while
something is still working in it. A worktree you or a tool added by hand is
shown, never touched.

A project has no `workspace:` section until somebody chooses something: the
`agents.yaml` uze creates says nothing about the workspace, and every key is in
the [reference](/docs/reference/project-files#workspace). Once one is chosen, the workspace keeps a "Concurrent work
isolation" section in `AGENTS.md` in step with it, in your checkout, for the
agents it launches. To stop, remove the values again; the workspace takes
the section back the next time it runs. The agents themselves carry the part
no harness does for them with the `uze:worktree` skill.

## Its work gets a name

An agent in a worktree names its own branch as the first thing it does, like
`fix/login-timeout`. That name is what you read in the sidebar and what a
reviewer sees on the pull request. You never have to name anything.

## Where it stands

The tab shows where the work is, read from Git rather than from what the agent
says:

| | |
| --- | --- |
| **Running** | Working, nothing committed yet |
| **Ready** | Committed, nothing left uncommitted |
| **Conflicted** | Needs the agent to settle a rebase |
| **Integrated** | The work is in your target branch |

## Bringing the work home

When an agent in a worktree is **Ready**, press `Alt+I` to deliver it. The branch is
rebased onto your target branch, your checks run, and then comes what the
project chose:

```yaml
workspace:
  delivery: pr       # handoff (default) | merge | pr
  gate: npm test     # the checks that must pass first
```

- **handoff** leaves the branch for you to merge.
- **merge** fast-forwards the target branch.
- **pr** pushes the branch and opens a pull request with `gh` or `glab`.

If the checks fail or the rebase conflicts, nothing reaches the target and the
agent gets the problem back.

## Subagents

An agent that splits its work across subagents asks uze for a checkout for
each one, the same way it names its work:

```bash
uze agent work split parser   # a checkout cut from the agent's commit, printed as a path
uze agent work join parser    # the subagent's commits land on the agent's branch
```

The subagent's checkout comes from the same pool, so it starts warm. Joining
replays its commits onto the agent's branch with no merge commit. The checkout
stays until it is joined or the agent ends, and an agent is not delivered while
a subagent still holds work.

## Work nobody finished

Close an agent with commits still on its branch and the work is kept, not lost.
`Alt+P` opens **Work**, which lists every project with kept work or a space
open on it, each with how many of its items need you and how much disk its
checkouts take.

Choose a project to see one list of everything it holds: the work uze kept and
every checkout of the project, whoever made it. Each row is named by its branch
and grouped by what it asks of you:

- **Needs you**: kept work nobody is working on. A task that stopped with
  uncommitted changes, a conflict or failed checks, a checkout of uze's still
  holding work, a subagent waiting to be joined, or a task whose checkout is
  gone and whose branch still holds the work.
- **In progress**: a checkout with something running inside it, or one a live
  agent is working in.
- **Ready for the next agent**: checkouts uze keeps clean and ready, so the
  next agent starts at once.
- **Others**: your own checkouts and the ones a harness keeps for itself, with
  their facts. What they hold is yours to decide.

The buttons change with the row you select. Resume a kept task with a new
agent (`Enter` or `r`), deliver it, or mark it done. Open a space on a checkout
that holds no task, join a subagent into its agent, or adopt a checkout you made
under `.worktrees/` so uze can reuse it. `d` discards a task, deleting its checkout
and its branch, or removes a checkout that holds no task, keeping its branch.
Both ask first. Clean up removes, in one step, every checkout of yours that is
clean, unused and already in the target.
