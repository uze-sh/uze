**The package manager for coding agents.** Give Claude Code, Codex,
OpenCode and Antigravity the same plugins and one `AGENTS.md`, each in its own
format. Then run several agents at once, each in a
git worktree of its own.

uze is not a coding agent. It has no model, makes no LLM calls and needs no API
key: your agents keep the logins and subscriptions they already have, and uze
works around them.

Two tools, one binary. Each works without the other; use either, or both.

## The package manager

**It delivers your tooling.** Install a plugin once and every agent receives it
through its own native mechanism. Write one `AGENTS.md` and every agent reads
it. A project records its plugins in `agents.yaml`, so whoever clones it gets
the same ones.

It is a plain CLI (`uze install`, `uze market`, `uze status`). The agents it
serves are the ones you already start the way you always have, in your own
terminal, your editor or CI.

## The workspace

**It runs your agents.** `uze workspace` opens a terminal workspace
where every agent gets a tab, a branch and, if you want, a checkout of its own.
You see what each one changed, and bring the work home when it is ready.
Closing it stops nothing.
[The workspace →](/docs/workspace)

## Together

Every agent the workspace starts already has the plugins and the instructions
the package manager delivered, and the workspace's management screen
(`Ctrl+O`) handles the same plugins and marketplaces with the mouse. Neither
is required for the other: a project can use only the plugins, or only the
workspace.
