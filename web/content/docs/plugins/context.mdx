title: AGENTS.md
description: One AGENTS.md that every agent reads
---

Write your project's instructions once, in `AGENTS.md` at the project root.
Every agent reads it natively: Claude Code, Codex, OpenCode and Antigravity.

## Set it up

Ask any agent, with the `uze:init` skill:

```text
/uze:init
```

It reads your project and whatever instructions already exist (`CLAUDE.md`,
`GEMINI.md`, …), proposes one `AGENTS.md`, and changes nothing until you agree.

## Check it

```bash
uze status
```

Says which file your instructions come from and whether every agent reads it.
If one does not, `uze install` fixes it.

## What uze writes into it

Nothing. `AGENTS.md` is yours, and no uze command adds to it or changes it.

What a plugin asks of every agent in your project arrives as a rule with
`trigger: always_on`, copied into `.agents/rules/` when your `agents.yaml`
declares the plugin ([Rules](/docs/plugins/rules)). An agent the workspace
launches gets its own instructions (where it works, how its work is
delivered, how to name it) with its context when it starts
([Agents](/docs/workspace/agents)), and an agent asked to write a plugin
follows the `uze:author` skill.

Earlier releases wrote blocks into `AGENTS.md`, marked like this:

```markdown
<!-- uze:begin … -->
…
<!-- uze:end … -->
```

and a one-line `CLAUDE.md` that imported `AGENTS.md` for Claude Code. In your
main checkout, `uze install` removes those blocks once and leaves your own
text as it was. A block you edited by hand is reported and left for you. The
`CLAUDE.md` goes with the last block, or keeps your own lines if you wrote
any. Commit the result once; checkouts made after that are clean.

## Project skills, agents and rules

Skills the project keeps in `.agents/skills` reach Codex, OpenCode and
Antigravity natively, wherever you start them. Agents in `.agents/agents` reach
Antigravity natively. Claude Code reads neither, and Codex does not read project
agents, so for those two they arrive through the workspace's shim: inside
`uze workspace` only. OpenCode does not receive project agents at all, because
nothing a launch hands it stays with one project. `uze status` and
`uze inspect` say which. Plugins you
install are not affected: they reach every agent everywhere.

Rules the project keeps in `.agents/rules` reach every agent, inside the
workspace or out of it: Antigravity reads them natively, and Claude Code, Codex
and OpenCode receive them through the rules engine `uze setup` installs. See
[Rules](/docs/plugins/rules).

The workspace shows the same answer per agent: the harness's details under
**Manage** and the agent's section of the space view list `AGENTS.md`,
`.agents/skills`, `.agents/agents` and `.agents/rules`, each with how it reaches
that agent.
