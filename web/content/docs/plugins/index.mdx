Install a plugin once, and every agent you use gets it: Claude Code, Codex,
OpenCode and Antigravity, each in its own format. A plugin bundles skills, MCP
servers, agents, hooks and rules.

Your project records its plugins, so whoever clones it gets the same ones.
They reach the agents you start yourself, in a terminal, an editor or CI, and
the ones [the workspace](/docs/workspace) starts. The package manager is a
plain CLI and does not need the workspace.

## Installing a plugin

```bash
uze <plugin>@<marketplace>    # add it to this project
uze inspect <plugin>          # what it carries, and how each agent receives it
uze remove <plugin>           # take it out of this project
```

A plugin that runs commands on your machine (an MCP server, a hook, a skill
that runs a command when it loads) lists them and asks before installing.

## Your project remembers

Adding a plugin writes two files at the project root. Commit them:

- `agents.yaml`: the plugins this project wants.
- `agents.lock`: the exact version each one resolved to.

Anyone who clones the project gets the same plugins, at the same versions:

```bash
git clone …
uze install
```

## Updating

```bash
uze update             # every plugin, to the newest version
uze update <plugin>    # just one
```

`uze install` never moves a version; `uze update` does, and rewrites
`agents.lock`.

Each agent receives a plugin through its own native mechanism.
[How delivery works](/docs/plugins/delivery) explains the routes and what keeps
them safe.

## Only on this machine

To install a plugin for yourself without writing it into the project, add `-m`:

```bash
uze install <plugin>@<marketplace> -m
uze remove <plugin> -m
```
