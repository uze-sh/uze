## Ask an agent

The fastest way is to describe what you want, with the `uze:author` skill:

```text
/uze:author create a plugin with a skill that writes our release notes
```

The agent picks or creates a marketplace, scaffolds the plugin, checks it, and
installs it. Then you iterate on the files, and deliver each change to your
agents with `uze update <plugin> -m`.

## What a plugin is

<Files>
  <Folder name="my-plugin" defaultOpen>
    <Folder name="agents">
      <File name="planner.md" />
    </Folder>
    <Folder name="rules">
      <File name="conventions.md" />
    </Folder>
    <Folder name="skills">
      <Folder name="release-notes">
        <File name="SKILL.md" />
      </Folder>
    </Folder>
    <File name="hooks.json" />
    <File name="mcp.json" />
    <File name="plugin.json" />
  </Folder>
</Files>

Only `plugin.json` is required; ship what you need. A rule under `rules/` is
how a plugin tells the agents of every project that declares it something
([Rules](/docs/plugins/rules)). These are open standards
([Agent Plugins](https://agent-plugins.org), [Agent Skills](https://agentskills.io),
MCP), not a uze format, so a plugin written for uze is a plugin for everyone.

A skill is a folder with a `SKILL.md`:

```markdown
---
name: release-notes
description: Write release notes from the commits since the last tag
---

What the agent should do when this skill runs.
```

## Try it and share it

Install the plugin from its marketplace, and deliver each change you make to
your agents:

```bash
uze install -m my-plugin@my-market   # install it
uze update my-plugin -m              # after each change
```

To publish, push the marketplace repository. Anyone can then
`uze market add` it.

A marketplace can also live inside the project itself, versioned with it. To
scaffold and check plugins without the skill, see the authoring commands in
[Agent CLI](/docs/reference/agent-cli).
